## 1. 问题定义（论文摘要+引言）

遥感目标检测：从卫星/航空影像中**定位并识别**车辆、船舶、建筑物等目标。
应用：资源勘探、灾害评估（洪水/火灾/地震）、军事目标识别。

**现有方法的三个矛盾**（这就是论文立题）：

1. **精度↑ 却 部署难**：深度模型动辄几十 M 参数、几十 GFLOPs，无人机/星载设备扛不住；
2. **实时性不足**：应急响应、军事场景要求近实时，大模型 FPS 上不去；
3. **小目标精度差**：遥感目标普遍偏小，特征在深层被"压缩稀释"，易被背景掩盖。

**论文的目标函数**（工程语言）：在 mAP 不降的前提下，把 Params、GFLOPs 压下去，
同时保住 FPS —— 三维平衡：体积、效率、性能。

## 2. 技术选型：为什么是 YOLOv11s 做基线（2.0 节）

- YOLO 系是单阶段检测的**速度标杆**，与"实时遥感"诉求天然匹配；
- **v11s**：s 档参数量 9.43M / 21.5 GFLOPs，是"精度-体积"的甜点档；
  n 档太弱（小目标检测撑不住），m/l/x 档部署压力大；
- 社区生态成熟（ultralytics），便于模块替换与工程落地。

论文实验环境（3.1.1 节）：RTX 2070S 8GB，Python 3.10 + PyTorch 2.0.0 + CUDA 11.8，
batch=8，epoch=200，SGD（lr=0.01，momentum=0.9，weight_decay=0.0005）。
→ 本项目复现环境：RTX 4060 8GB + ML2 环境，超参完全一致（docs/09）。

## 3. 四大改进与"三位一体"框架（2.1 节）

论文的自述框架：**轻量化（DSNRblock+GhostConv）— 特征融合（BiFPN）— 损失优化
（自适应混合损失）** 三位一体：

```
                ┌────────────────────────────────────────┐
                │            输入 640×640                  │
                └───────────────┬────────────────────────┘
        主干 Backbone（论文图1 左列，0~10 层）
  0 Conv ↓2   ┌────────────────────────────┐
  1 Conv ↓2   │ v11 原样                     │
  2 ★DSNRblock│ ← 改进①：换掉 C3k2           │
  3 ★GhostConv↓2 ← 改进②：换掉下采样 Conv    │
  4 ★DSNRblock│                             │
  5 ★GhostConv↓2   → 输出 P3 (80×80) 侧向───┼───┐
  6 ★DSNRblock│   → 输出 P4 (40×40) 侧向───┼─┐ │
  7 ★GhostConv↓2                            │ │ │
  8 ★DSNRblock│                             │ │ │
  9 SPPF     │                             │ │ │
 10 C2PSA ───┼───→ 输出 P5 (20×20) 侧向────┼─┼─┤
             └────────────────────────────┘ │ │ │
        颈部 Neck（图1 中/右列，BiFPN）      │ │ │
 11~13 三路 1×1 侧向对齐 ◄─────────────────┘ │ │   （对应 yaml head 11~13）
 14 Upsample → 15 BiFPN融合 → 16 C3k2 ───────┘ │   （自顶向下）
 17 Upsample → 18 BiFPN融合 → 19 C3k2 = P3输出─┼─→ 20 GhostConv↓2
 21 BiFPN三路融合 → 22 C3k2 = P4输出───────────┼─→ 23 GhostConv↓2
 24 BiFPN融合 → 25 C3k2 = P5输出               │
        检测头（图1 右列）                      │
 26 Detect(P3, P4, P5) ◄──────────────────────┘
```

（`★` = 论文改动点。上图为图1 的逻辑等价重画，逐层通道数见 yaml 注释。）

**四个改进各管一件事**：

| # | 改进 | 管什么 | 为什么放在那个位置 |
|---|---|---|---|
| ① | DSNRblock | 主干特征提取的"性价比" | 主干是参数大户（v11s 里占 5.44M） |
| ② | GhostConv | 下采样与颈部融合的冗余 | 下采样卷积通道大、参数密集 |
| ③ | BiFPN | 多尺度融合质量 | 轻量化必然丢精度，用融合质量补回来 |
| ④ | 混合损失 | 训练信号的分配 | 让有限的模型容量花在难样本/低质量样本上 |

> 论文消融表2 的顺序正是 ①→②→③→④ 逐个叠加，最终 9.43M→7.15M（−24.2%），
> 21.5→18.3 GFLOPs（−14.9%），mAP50 88.4→89.0（+0.6），mAP 66.2→66.9（+0.7）。

## 4. 图1 的"检测头"细节

图1 右列三个 DETECT 分别接 C3k2 22（P3，小目标）、25（P4，中目标）、28（P5，大目标）。
本复现把颈部简化为标准三尺度 BiFPN（16 层，11~26），层数与论文（18 层，11~28）
略有差异——论文未公开颈部全部连线细节，复现采用 EfficientDet 的规范拓扑，
**层数差异不影响四个改进点的对齐**。详见 docs/05 的"复现说明"。

## 6. 论文没有明说、但你需要知道的四件事（复现者视角）

1. **输入尺寸未写明**：由基线 GFLOPs 反推为 640×640（yolo11s@640=21.5 GFLOPs
   与表2完全吻合）；本复现按 640 训练。
2. **是否用 COCO 预训练权重未写明**：主干模块被替换后预训练权重大部分用不上，
   按从零训练处理（200 epoch 与论文一致）。
3. **BiFPN 连线/通道细节未公开**：采用 EfficientDet 规范拓扑（见 docs/05）。
4. **损失系数（γ、μ、α、β）未公开**：按 SLIDE/ATFL 原论文思想取常用值，
   全部暴露在 `mixed_loss.py` 的 `__init__` 里可调。

> 这四点就是"读论文复现"的日常：论文给思路和结果，复现者负责把每个未公开细节
> 变成**可运行、可辩驳的选择**，并把它们全部写进注释里（本项目正是这么做的）。
