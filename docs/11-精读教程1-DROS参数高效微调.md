## 2. 前置概念：五个台阶，逐个上

### 台阶 1：什么是"基础模型"，为什么微调它很贵

**基础模型（foundation model）**：在海量通用数据上预训练好的大模型，如 CLIP
（图文对齐）、DINOv2（视觉特征）、RingMo/CROMA（遥感领域的预训练模型）。
它们像一个"什么都懂一点的全科医生"，但遇到你的具体任务（比如"识别 SAR 图里的
油罐"）还需要**微调（fine-tuning）**。

**全参数微调（full fine-tuning）的问题**：基础模型的每一个权重都要更新——
一个 3 亿参数的模型就要存 3 亿个梯度、优化器状态（Adam 要额外存 2 倍参数量的
动量/方差），显存和时间都是天文数字；而且每做一个下游任务就要**完整保存一份
模型副本**。十个任务 = 十份 3 亿参数的模型，存储爆炸。

### 台阶 2：PEFT——"冻住主干，只训一点点"

**参数高效微调（Parameter-Efficient Fine-Tuning, PEFT）**的思路：冻结全部预训练
权重，只在网络里**插入少量新的可训练参数**。家族成员：

| 方法 | 插入什么 | 直觉 |
|---|---|---|
| Adapter (2019) | 每层插一个小瓶颈 MLP | 挂"外挂模块" |
| Prefix/Prompt | 在输入序列前加可学习 token | 递"小抄" |
| **LoRA (2021)** ★ | 给权重矩阵配一个低秩旁路 | 给权重"打小补丁"（本文的基础） |

LoRA 是本文的直接对照对象，必须吃透 → 下一个台阶。

### 台阶 3：LoRA——用两个瘦矩阵的乘积表示权重更新

微调时，每个权重矩阵 W 的真实变化量是 **ΔW**（全参数微调就是直接学 ΔW）。
LoRA 的观察：ΔW 虽然矩阵很大，但它的"有效信息"往往集中在少数方向上——
可以用**两个瘦矩阵的乘积**来近似：

```
        全量微调:  h = (W + ΔW)x            ΔW 是 d×d 大矩阵，全训
LoRA:      h = Wx + (B·A)x                  W 冻结；只训 A(d×r)、B(r×d)
                                             r ≪ d（秩 rank，典型 r=4~16）
```

**参数量手算**（感受一下"高效"）：d=1024, r=8：

```
全量 ΔW：1024 × 1024        = 1 048 576 个参数
LoRA：   1024×8 + 8×1024    =    16 384 个参数      → 只有 1.6% ！
```

**两处关键性质**（DROS 的设计都围绕它们）：
1. **低秩 = 限制了更新所在的方向集合**。A 先把输入 x 投影到 r 维的"小空间"，
   B 再从小空间投回 d 维——ΔW 的所有可能取值都活在 r 维张成的**子空间**里。
   r 维子空间里"放"哪个方向，决定了你那 1.6% 的预算花在哪；
2. **可合并**：训练完直接算 W' = W + BA 存回模型——部署时结构与原模型
   **一模一样，推理零额外开销**（Adapter 那种外挂模块做不到）。

### 台阶 4：什么是"子空间"、SVD 是什么（本文的数学核心）

**向量空间/子空间**的直觉版：一个 d 维空间里的"子空间"就是一张过原点的
"低维平面"。r=8 意味着你的微调只能在一张 8 维的"平面"上做文章。
**子空间的方向选得好不好，直接决定这 1.6% 预算的效率。**

**SVD（奇异值分解）**是找"最重要方向"的标准数学工具：任何矩阵 M 都能分解为

```
M = U Σ Vᵗ      U、V 是"方向"（正交基），Σ 是对角线上排好序的"重要性分数"（奇异值）
```

直觉：把 M 看成"把输入空间拧到输出空间"的一套动作，SVD 告诉你这套动作
**主要由哪几个方向构成、各占多少分量**。取最大的 r 个方向 = 最优 r 维近似
（Eckart–Young 定理保证这是截断误差最小的选择）。

### 台阶 5：什么是"正交"，为什么本文要"松弛正交"

**正交（orthogonal）**= 互相垂直。正交变换（旋转/镜像）的特殊性质：
**不拉伸、不压缩任何方向**——只转动，不改写长度比例。

对微调来说这意味着什么？预训练模型内部的几何结构（特征之间的角度关系）
是它在亿级数据上学到的"世界观"。如果适配算子是**严格正交**的，就能在适配
新任务的同时**最大程度保留**这套世界观（不过度扰动预训练几何）。

但严格正交也**太死板**：遥感任务有时需要真正改写特征关系（域差太大）。
所以 DROS 用"**松弛**正交"——带自适应缩放、近似正交的变换，在
"保结构（正交的极端）"和"完全自由（会破坏预训练几何的极端）"之间取折中。
⚠️ 日报未给出该算子的具体公式，以上是按其命名与描述的原理性解读。

## 3. DROS 方法精读（三个组件）

### 3.1 问题定位：什么是"子空间失配"（subspace mismatch）

LoRA 的 A、B 通常**随机初始化**（B 置零保证起点等价于原模型），更新方向的
子空间是"数据无关"的。这在域差小的 NLP 任务上问题不大；但遥感数据的域偏移
极大——**季节（夏/冬）、传感器（光学/SAR）、地理场景（城市/荒漠）**——
随机的 r 维子空间，很可能把宝贵容量分配给下游数据**根本不活跃**的方向：

```
        d=1024 维权重空间
        ┌─────────────────────────────┐
        │  ~~~ 随机 LoRA 子空间(r=8)    │   ← 力气花在这里（数据不活跃）
        │                             │
        │      ▓▓▓ 下游数据活跃方向     │   ← 真正该花力气的地方
        │      ▓▓▓（遥感域特有的特征）   │
        └─────────────────────────────┘
                 "子空间失配" 示意
```

### 3.2 组件①：数据条件初始化（DRAI）——"先把预算分对方向"

> 论文原话（日报转载）：*用下游数据激活协方差矩阵 C 与权重 W 的乘积 W·C 进行
> 奇异值分解，以其 bottom-r 特征值/向量对低秩适配算子做数据条件初始化。*

拆开读（每一步为什么合理）：

1. **激活协方差 C**：拿少量下游训练图过一遍模型，统计每层激活的协方差——
   C 的大特征值方向 = 遥感数据在这个层**真实活跃**的特征方向；
2. **W·C 做 SVD**：单纯看 W 的 SVD 得到的是"预训练认为重要的方向"；
   乘上 C 相当于**用下游数据给 W 的方向重新加权**——遥感里活跃的方向排前；
3. **用分解得到的方向初始化低秩算子**：适配的起点不再是随机平面，
   而是与数据分布对齐的平面。⚠️ 日报写的是 "bottom-r"（取小的 r 个特征值/向量），
   该选择与 LoRA-GA/PiSSA 等工作中"主成分/补空间"的取舍 debate 相关——
   原文细节以正式版为准；**你只需记住设计意图：让初始化"看"过下游数据。**

一句话：**组件①解决"容量分给谁"。**

### 3.3 组件②：松弛正交算子——"容量怎么花不伤身"

在两个低秩基之间插入一个带自适应缩放的近似正交变换（见台阶 5 的直觉）。
两个极端都不好：

```
严格正交 ──→ 完美保留预训练几何，但几乎"转不动"，适配能力不足
完全自由 ──→ 适配能力强，但会改写预训练几何，灾难性遗忘风险大
松弛正交 ──→ 大体保结构，允许局部自适应伸缩（折中）★DROS 的选择
```

一句话：**组件②解决"花预算的方式"，防止"学会了新任务、忘了旧世界"。**

### 3.4 组件③：MM-DROS——多模态扩展（本文标题里的 Multimodal）

遥感基础模型常常是**多模态**的（光学 + SAR + 高光谱……）。每个模态的数据
统计特性差别很大（SAR 是相干成像、带斑点噪声），共享一套适配参数会"水土不服"；
每个模态**完全独立**又浪费跨模态共性。

MM-DROS 的折中：**模态专属的低秩基 + 各模态间共享的紧凑变换算子**——
"各过各的日子，但走同一条高速通道"。⚠️ 具体共享结构日报未详述，按此直觉理解即可。

### 3.5 三组件协同图

```
下游遥感数据 ──统计──► 激活协方差 C ──SVD(W·C)──► 数据条件初始化 ┐
                                                              │  子空间选对了方向
                                                              ▼
预训练权重 W（冻结）◄──松弛正交算子（保结构）◄──低秩更新 ◄────────┘  花法不伤身
                                                              │
                                          多模态：各模态基 + 共享紧凑变换（MM-DROS）
```

## 4. 实验解读（基于日报结论 + 通用判读方法）

日报结论：**"在多个遥感基准上超越 LoRA 等 PEFT 基线，甚至超过全参数微调，
且无额外推理延迟。"** ⚠️ 日报未附具体表格，读正式版时按下面清单核对：

1. **对比对象齐不齐**：至少要有 LoRA、Adapter、(理想情况) 全参数微调 + 另一个
   数据感知初始化方法（如 PiSSA/LoRA-GA 类）——否则"超过 LoRA"说服力打折；
2. **参数预算对齐了吗**：不同 PEFT 方法可训参数量必须一致（比如都 r=8），
   否则是"参数多的赢参数少的"，不算赢；
3. **"超过全参数微调"怎么读**：这在 PEFT 文献里出现时，通常不是"容量更大"，
   而是**低秩约束起到了正则化作用**——小数据集上全参数微调更容易过拟合。
   这是个合理且常见的现象，但要用多个数据集/多个种子验证；
4. **"无额外推理延迟"**：来源是第 2 节讲的"可合并"性质（W'=W+BA 存回），
   这是 LoRA 系方法共有的卖点，DROS 继承之。

## 5. 接入主线课程：轻结构 vs 轻训练

| | DSNR-YOLO（主线） | DROS（本篇） |
|---|---|---|
| 轻"什么" | 网络结构小（7M 参数、18 GFLOPs） | 训练时动的参数少（~1.6%） |
| 假设的瓶颈 | 边缘设备推理跑不动 | 基础模型全参数微调训不起/存不下 |
| 部署形态 | 独立的小模型 | 原模型 + 合并后的补丁（零开销） |
| 精度来源 | 架构设计（注意力/融合/损失） | 预训练模型的通用知识 + 对准方向的少量适配 |
| 适合场景 | 从零训练专用检测器 | 已有强基础模型、多个下游任务快速适配 |

**两者可以杂交**：用轻量检测器做推理端，用 DROS 式适配做多域数据迁移——
这是很现实的开题方向（详见 docs/10 第三节）。

## 6. 自测（答案在括号内，先别偷看）

1. LoRA 为什么能省 98% 的参数？（答：ΔW 用低秩 BA 近似，d×d → 2×d×r，r≪d）
2. "子空间失配"是什么意思？（答：随机初始化的低秩子空间与下游数据活跃方向
   不对齐，微调容量浪费在数据不活跃的方向上）
3. DROS 组件①的"数据条件初始化"对随机初始化做了什么改进？（答：用下游激活
   协方差加权 W 后 SVD，让初始方向看"过"遥感数据的分布）
4. 为什么"松弛"正交比"严格"正交好？（答：严格正交保结构但适配能力不足；
   松弛在保留预训练几何与适配自由度间折中）
5. 训练完怎么做到"推理零开销"？（答：低秩矩阵可合并：W'=W+BA）
