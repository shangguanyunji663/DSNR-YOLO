## 1. 环境准备（只动 ML2，不碰 base！）

```bash
# 激活 ML2 环境（本机已有：Python 3.12.12）
conda activate ML2

# ① 安装 CUDA 版 PyTorch（RTX 4060 用 cu128 源；不要用默认源，那装的是 CPU 版！）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

# ② 安装 ultralytics 及依赖
pip install -r requirements.txt

# ③ 验证 GPU 可用
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# 期望: 2.11.0+cu128 True NVIDIA GeForce RTX 4060 Laptop GPU
```

> ⚠️ 坑1：`pip install ultralytics` 可能会把你刚装的 CUDA torch 替换成 CPU 版
> （PyPI 默认源在 Windows 上只发 CPU wheel）。**装完 ultralytics 后务必重新执行
> ①**，或按 `--force-reinstall torch==x.y.z+cu128 torchvision==x.y.z+cu128
> --index-url .../cu128` 成对修复（torch 与 torchvision 必须配对）。
>
> ⚠️ 坑2：**全程不要用 base 环境**，也不要 `pip install` 到 base。

## 2. 三级验证（环境 → 模块 → 整网）

```bash
# 一级：模块单元测试（8 个，对应论文全部公式）
python tests/test_modules.py

# 二级：整网自检（构建/参数量/前向形状/损失反传，无需任何数据）
python scripts/verify_model.py
#    期望：总参数量 ≈ 6.01M（论文 7.15M，差异见 docs/05）
#          三尺度特征图 (1,128,80,80)/(1,256,40,40)/(1,512,20,20)
#          ω1/ω2 收到梯度

# 三级：玩具数据集冒烟训练（~1 分钟，证明端到端全通）
python scripts/make_toy_dataset.py
python scripts/train.py --data data/toy.yaml --epochs 3 --imgsz 320 --batch 4 --nbs 4 --device 0
```

> ⚠️ 坑3（重要）：`--nbs 4`（=batch）。ultralytics 默认 nbs=64，小数据集
> 小 batch 时梯度累积 16 步才更新一次，而每轮只有 10 个 batch →
> **整个训练一次 optimizer.step 都不会发生**（所有损失数值原地踏步）。
> 正式训练 batch=8 时默认 nbs=64 → accumulate=8，恰好每批更新一次，无需设置。

冒烟通过标准：3 轮跑完、`runs/toy_smoke/weights/best.pt` 生成、
最后验证阶段能打印各类别指标（数值接近 0 是正常的——40 张随机图训 3 轮学不到东西）。

两者需手动下载（注册/网盘），获取途径与目录要求见 `data/README.md`。

```bash
# 编辑 data/dior.yaml：把 path 改成转换输出目录的绝对路径，names 与脚本打印的
# 类别对照表核对一致
```

## 4. 正式训练（超参 = 论文 3.1.1 节）

```bash
python scripts/train.py --data data/dior.yaml --epochs 200 --imgsz 640 --batch 8 --device 0 --name dsnr_dior
```

脚本内置：`optimizer=SGD, lr0=0.01, momentum=0.9, weight_decay=0.0005`（论文值）、
`seed=0`（可复现）。8GB 显存跑 640px/batch8 约占 5~6GB，若 OOM 见下表。

训练时间参考：RTX 4060 上 DIOR（1.87 万训练图）约 3~5 h/100 epoch，
论文的 200 epoch 需要一晚。

## 5. 评估与结果对照

```bash
python scripts/val.py --data data/dior.yaml --weights runs/dsnr_dior/weights/best.pt --device 0
# 测试集：加 --split test
```

对照论文（DIOR 测试集）：

| 指标 | 论文 DSNR-YOLO | 你的复现（参考区间） |
|---|---|---|
| mAP50 | 89.0% | 87~89%（受实现细节/随机性影响） |
| mAP50-95 | 66.9% | 64~67% |
| Params | 7.15M | 6.01M（本复现颈部更精简，docs/05） |
| GFLOPs | 18.3 | ≈16~18 |
| FPS | 128 | 以本机 4060 实测为准 |

复现结果**不等于**论文数字是常态：数据划分随机性、未公开的颈部/损失细节、
训练轮次中的随机增广等都会造成 ±0.5 级别漂移。重要的是**趋势复现**：
参数量显著小于基线、精度不低于基线。

## 6. 常见问题排查表

| 症状 | 原因 | 处理 |
|---|---|---|
| `CUDA out of memory` | 640px batch8 超 8GB 显存 | batch 降为 4（nbs 仍 8 可保持等效批），或 imgsz 512 |
| `operator torchvision::nms does not exist` | torch/torchvision 版本不配对 | 见第 1 节坑1，成对重装 |
| 损失几十轮不降、ω 恒为 1.0 | nbs 太大，梯度累积从不触发 | 设 `--nbs` = batch |
| `KeyError: 'DSNRblock'` | 训练脚本没先 `register.apply()` | scripts/train.py 已处理；自写脚本要记得 |
| 训练 loss=NaN | lr 太大或数据有坏框 | 转换脚本会裁剪越界框；可把 lr0 降到 0.001 试 |
| 中文路径读图失败 | cv2 老接口不支持 | 本项目所有读写已用 `imencode/tofile` 处理 |
| Windows 报 DataLoader worker 崩溃 | 线程数多 | 已默认 workers=2，还可改 0 |

## 7. 推荐实验路线（把论文"变成自己的"）

1. **消融复现**：改 yaml 逐个还原四项改进，重训对比（≈论文表2）；
2. **门控可视化**：训练后打印 4 个 DSNRblock 的 nam_gate.sigmoid()，
   看哪些层更依赖注意力（docs/04 第 7 节）；
3. **BiFPN 权重可视化**：打印融合权重，验证"浅层权重更大"（docs/05 第 5 节）；
4. **ω 演化曲线**：每 epoch 记录 w_atfl/w_slide，验证式(11) 正则的作用
   （docs/06 第 5 节）；
5. **自己的模块**：往 MODULE_REGISTRY 加一个模块接进 yaml —— 走通即出师。
